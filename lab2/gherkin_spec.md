# Use-case: Створити постачання

## Сценарії

Розглянути:
* успішне створення постачання з кількома позиціями
* спробу створення без авторизації або прав
* відсутні чи неіснуючі обов’язкові реквізити
* неактивного відповідального працівника
* неіснуючий продукт, недодатну кількість, від’ємну ціну та відсутність позицій
* перевірку всіх позицій: одна коректна позиція не компенсує помилку в іншій
* допустимі граничні значення
* запит на сповіщення лише після збереження
* недоступність сервісу сповіщень без втрати постачання
* повтор сповіщення після відновлення сервісу
* локальне збереження введених даних без доступу до сервера, без створення постачання на сервері та без сповіщення

## Критерії прийняття
* У файлі gherkin.feature має бути один Feature
* В описі Feature зазначити user story у форматі As a… I want… so that… для менеджера магазину або адміністратора
* Використовувати англійські ключові слова Gherkin та український текст кроків
* Надати сценаріям унікальні теги
* Для кожного сценарію вказати пов’язані вимоги. Якщо вимоги ще не мають ID у джерелі, навести їхні точні формулювання в окремих примітках.
* Приймання постачань, перегляд залишків та кешування результатів перегляду не включати до цього Feature.
